One app, one database. The website and its backend routes are the same Next.js app, so there is only one thing to deploy.

Code changes needed

Uploaded files are saved in a storage/ folder inside the project (created automatically). To keep them somewhere else, add UPLOAD_DIR=/home/SITE-USER/pitchprox-uploads to .env.local.

None. You only create one settings file on the server. Database name, user, password and mode all come from .env.local (step 5). The app creates its own tables the first time it runs — you don't import any SQL.
Don't use the GitHub auto-deploy yet .github/workflows/deploy.yml stops when lint fails (48 old errors left in admin/rep screens), and it doesn't install packages on the server. Its rsync --delete would also wipe the uploaded files in storage/. Deploy by hand with this guide until we fix it in a later module.

1. Create the site

  1. Log in to CloudPanel: https://YOUR-SERVER-IP:8443
  2. Sites → + Add Site → Create a Node.js Site
  3. Domain name: e.g. app.pitchprox.com · Node.js version: 22 LTS · App Port: 3000 (any free port — remember it)
  4. CloudPanel creates a site user and password — save both. Your files live in /home/SITE-USER/htdocs/YOUR-DOMAIN/

2. Domain & HTTPS

  1. At your domain registrar, add an A record: app → your server IP. Wait until it works (a few minutes to an hour).
  2. In CloudPanel: open the site → SSL/TLS → Actions → New Let's Encrypt Certificate → Create.
HTTPS is required, not optional The login cookie is marked "secure" in production, so browsers only send it over HTTPS. On plain http:// people can't stay logged in.

3. MySQL database

  1. In CloudPanel: Databases → Add Database (inside your site, or the main Databases menu).
  2. Database name: pitchprox · User: pitchprox_app · Password: click generate, then copy it somewhere safe.
  3. That's it — CloudPanel gives this user full rights on this one database, which the app needs (it creates and updates its own tables).

Host is 127.0.0.1, port 3306. Never open port 3306 to the internet.

4. Upload the code

Connect as the site user (not root). In CloudPanel open the site → SSH/FTP to see/add login details. Then pick one:

OptionHow
A. Git (best)
ssh SITE-USER@YOUR-SERVER-IP cd ~/htdocs/YOUR-DOMAIN ls -la # check: only CloudPanel's placeholder files should be here rm -rf ./* ./.??* # empty THIS folder only — double-check you ran the cd line above git clone https://github.com/YOUR/REPO.git .
B. SFTPUse FileZilla → connect with the site user → upload the project into htdocs/YOUR-DOMAIN/. Don't upload node_modules, .next, .git or your local .env.local.

5. The settings file (.env.local)

In the project folder on the server:

nano .env.local

Paste this, using your real database password from step 3:

NODE_ENV=production MYSQL_HOST=127.0.0.1 MYSQL_PORT=3306 MYSQL_DATABASE=pitchprox MYSQL_USER=pitchprox_app MYSQL_PASSWORD="paste-the-generated-password-here"

Save (Ctrl+O, Enter, Ctrl+X), then lock it so only you can read it:

chmod 600 .env.local

The port is not set here — Next.js picks its port before it reads this file. We pass it in step 7 instead.

6. Install & build

node -v # must say v22.x npm ci # installs packages (a few minutes) npm run db:migrate # creates the tables + default playbooks & plans (safe to repeat) npm run build # makes the production version
Small server (1–2 GB RAM)? The build may be killed for running out of memory. Ask your host or add swap (as root): fallocate -l 2G /swapfile && chmod 600 /swapfile && mkswap /swapfile && swapon /swapfile

7. Start it (PM2 keeps it running)

npm install -g pm2 pm2 start ecosystem.config.cjs # uses the port in that file (8765) — must match the App Port pm2 save pm2 status # should say "online"

Make it come back after a server reboot:

echo $PATH # copy what this prints crontab -e # add these two lines at the bottom: PATH=paste-what-echo-printed @reboot pm2 resurrect > /dev/null 2>&1

8. Check the vhost

CloudPanel writes the NGINX config (the "vhost") for you. Open the site → Vhost tab and check the main part points to your App Port:

location / { proxy_pass http://127.0.0.1:{{app_port}}/; proxy_set_header Host $host; proxy_set_header X-Forwarded-Proto $scheme; ... }
  • Keep the proxy part as it is. {{app_port}} is filled from step 1 — it must match PORT in ecosystem.config.cjs.
  • Add one line for uploads (AI training files go up to 50 MB): inside the server { } block that has listen 443, add client_max_body_size 60M; and click Save. Without it, larger uploads fail with "413 Request Entity Too Large".

9. Create the first admin

Customers sign themselves up on the website. Staff accounts are made on the server:

npm run create-user -- --email you@company.com --name "Your Name" --password "a-strong-password" --role super_admin

Use --role sales_rep for a sales rep. (Later, Step 2.2 of the build plan adds a screen for this.)

10. Test it

  1. Open https://YOUR-DOMAIN — the padlock should show.
  2. Sign up as a test customer → you land on the customer dashboard.
  3. Add a lead → refresh → it's still there (it's in MySQL).
  4. Sign out, sign in as your super admin → you land on /super-admin/dashboard.
  5. Check the log has no errors: pm2 logs pitchprox --lines 50

Updating later

cd ~/htdocs/YOUR-DOMAIN git pull # or upload the changed files npm ci npm run db:migrate # adds any new tables/columns from the update npm run build pm2 reload pitchprox

Back up first before big updates — two things:

  • Database: CloudPanel → Databases → Export (or mysqldump -u pitchprox_app -p pitchprox > backup.sql).
  • Uploaded files: the storage/ folder in the project (AI training material, ticket attachments): tar czf storage-backup.tar.gz storage.

Never delete .env.local or storage/ — neither is in Git, so git pull leaves them alone.
