PitchProX — Build Plan (Web App)

Role by role, module by module · 27 Oct 2026 · everything saves to MySQL · mobile-app API on hold

The rules we agreed
  • Website only for now. The mobile-app API (token login, OTP codes, push notifications) waits until you talk to the app developer.
  • One role at a time, one module at a time. Each module is tested before the next starts.
  • Everything saves to MySQL (same database you'll create in CloudPanel).
  • Pages that need the client (an account, a provider, a decision) or the app developer are not built — they get a clear yellow warning saying why.
Quick note on the word "API" The website still needs its own small backend routes to save to MySQL — that's how every button that "saves" works (Phase 1 already did this for leads and CRM). What we're holding is the public API for the phone app. Nothing extra to set up: the website and its routes deploy together as one app.

What I suggest we do first

Start: 0.1 Page status warnings → then 1.1 Playbooks The warnings make the whole site honest and demo-safe in one small step. Playbooks are the heart of the product (the AI coaches from them), they need no outside service, and the screens are already built — so the client sees a big feature become real.

Each module ends with: lint + build pass, automated tests against MySQL, and an update to ROADMAP.md.
